# Рядом

Android-приложение для поиска собеседников поблизости. Курсовая работа.

Два человека включают видимость и видят друг друга на карте, если каждый попадает в радиус
поиска другого. Один отправляет запрос на общение, второй принимает или отклоняет его.
После принятия появляется чат, который работает независимо от расстояния и видимости.

Подробная модель поведения — в документе
[docs/Архитектура_модель_состояний_v3.docx](docs/Архитектура_модель_состояний_v3.docx):
состояния, события, таблица переходов T1–T28 и инварианты.

## Что умеет

- Регистрация и вход по почте и паролю, профиль с фото, возрастом и интересами.
- Карта с кругом радиуса (1, 3, 5 или 10 км) и приблизительными точками людей рядом.
- Запросы на общение: отправка, принятие, отказ с паузой 24 часа до повтора.
- Блокировка: из чата либо вместе со вторым отказом одному и тому же человеку; разблокировка.
- Жалоба при блокировке; каждые 3 жалобы от разных людей отстраняют аккаунт
  на 24 часа, 3 дня, 7 дней, затем навсегда.
- Чат с доставкой сообщений в реальном времени и чтением истории без сети.

Точные координаты не покидают устройство: перед отправкой они привязываются к сетке
с шагом около 200 м.

## Стек

| Часть | Технологии |
|---|---|
| Клиент | Kotlin, Jetpack Compose, Clean Architecture + MVVM, Hilt, Room, MapLibre |
| Сервер | Supabase: PostgreSQL + PostGIS, Auth, Realtime, Storage |
| Тесты | JUnit (предметная область), pgTAP (серверная логика) |

## Что нужно установить

- [Android Studio](https://developer.android.com/studio) с Android SDK 37 и эмулятором.
- [Docker Desktop](https://www.docker.com/products/docker-desktop/) — в нём работает локальный сервер.
- [Supabase CLI](https://supabase.com/docs/guides/local-development). На macOS:

```bash
brew install supabase/tap/supabase
```

## Запуск

### 1. Скачать проект

```bash
git clone https://github.com/KMegor/nearby.git
```

```bash
cd nearby
```

### 2. Поднять сервер

Запустите Docker Desktop, затем в папке проекта:

```bash
supabase start
```

Первый запуск скачивает образы и занимает несколько минут. База создаётся автоматически
из файлов в `supabase/migrations`, дополнительных действий не нужно.

Когда команда завершится, сервер доступен по адресу `http://127.0.0.1:54321`,
веб-панель с содержимым базы — `http://127.0.0.1:54323`.

Остановить сервер: `supabase stop`. После перезагрузки компьютера его нужно запустить заново.

### 3. Запустить приложение

1. Откройте папку проекта в Android Studio и дождитесь окончания синхронизации.
2. Создайте эмулятор телефона в Device Manager, если его нет.
3. Нажмите Run.

Приложение уже настроено на локальный сервер: эмулятор обращается к компьютеру
по адресу `10.0.2.2`. На реальном телефоне этот адрес не работает — см. раздел
«Другой сервер».

### 4. Задать местоположение эмулятора

На боковой панели эмулятора: «⋯» → Location → введите широту и долготу → Set Location.
Например, 55.752 и 37.6206 (центр Москвы).

### 5. Зарегистрироваться

База после первого запуска пустая. Зарегистрируйте аккаунт в приложении с любой почтой:
подтверждение письмом на локальном сервере отключено.

## Как проверить на двух пользователях

Основные сценарии требуют двух людей рядом.

1. Запустите второй эмулятор и приложение на нём.
2. Задайте обоим эмуляторам одинаковые координаты.
3. Зарегистрируйте на каждом свой аккаунт и включите «Видимость» на вкладке «Карта».
4. В течение 30 секунд оба увидят друг друга на карте.

Дальше: нажмите на точку человека → «Начать общение», на втором устройстве откройте
вкладку «Запросы» и ответьте.

Полезно знать:

- Новые запросы и список чатов обновляются раз в 20 секунд. Мгновенно приходят
  только сообщения в открытом чате.
- Человек пропадает с карты, если его местоположение не обновлялось 30 минут.
  Оно обновляется, только пока приложение открыто и видимость включена.
- Чтобы не ждать 24 часа после отказа, откройте веб-панель → Table Editor → `connections`
  и сдвиньте `rejected_at` на сутки назад.

## Тесты

Серверная логика (нужен запущенный сервер). Названия проверок совпадают с номерами
строк таблицы переходов в документе:

```bash
supabase test db
```

Модульные тесты приложения — в Android Studio: правый клик по модулю `domain` →
Run 'Tests in domain'. Из терминала на macOS:

```bash
JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home" ./gradlew :domain:test
```

## Структура проекта

```
app/        экраны (Compose), ViewModel, навигация
domain/     сущности, сценарии использования, интерфейсы репозиториев — чистый Kotlin
data/       работа с сервером, локальный кэш, геолокация
supabase/
  migrations/   таблицы, правила доступа, функции переходов между состояниями
  tests/        автотесты серверной логики
docs/       документ с моделью состояний
```

Зависимости направлены только внутрь: `app` и `data` зависят от `domain`,
а `domain` не знает ни об Android, ни о сервере.

Вся логика переходов между состояниями выполняется на сервере. Клиент не может
записать в таблицы напрямую — только вызвать серверную функцию, которая проверит
условия и выполнит переход либо вернёт код отказа.

## Другой сервер

Адрес и публичный ключ сервера по умолчанию заданы в `gradle.properties`
и указывают на локальный Supabase. Чтобы подключиться к другому серверу
(например, к облачному проекту Supabase для запуска на реальном телефоне),
добавьте в файл `local.properties` в корне проекта:

```
supabase.url=https://<проект>.supabase.co
supabase.key=<публичный ключ проекта>
```

Файл `local.properties` не попадает в репозиторий. Схему базы в облачный проект
переносит команда `supabase db push` после `supabase link`.

Если локальный сервер выдал другой публичный ключ, его показывает `supabase status`
(строка Publishable key) — укажите его тем же способом.

## Возможные проблемы

| Симптом | Причина и решение |
|---|---|
| «Нет связи с сервером» | Сервер не запущен: `supabase start` |
| На карте пустой фон вместо улиц | Эмулятор не может узнать адрес сервера карт — обычно из-за VPN на компьютере. Запустите эмулятор из терминала с явным DNS: `~/Library/Android/sdk/emulator/emulator -avd <имя> -dns-server 77.88.8.8` (имена — `emulator -list-avds`). Круг и люди показываются и без подложки |
| Человек не появляется на карте | У обоих должна быть включена видимость и заданы координаты; подождите до 30 секунд |
| Видимость не включается | Нужно разрешение на точную геолокацию |
| Ошибка сборки про версию Java | Запускайте сборку из Android Studio либо укажите `JAVA_HOME`, как в разделе «Тесты» |

## Ограничения текущей версии

- Местоположение передаётся, только пока приложение открыто; фоновой службы нет.
- Нет push-уведомлений: о новом запросе или сообщении можно узнать, только открыв приложение.
- Нет ручной модерации жалоб: отстранение назначается автоматически.
- В чате только текст; сообщения нельзя редактировать и удалять.
- Интерфейс только на русском языке.
